## Current (Local) Topology

`docker-compose.yml` defines three services:

| Service | Image / Build | Port | Command | Notes |
| --- | --- | --- | --- | --- |
| `backend` | build `./backend` (`python:3.13-slim`) | 8000 | `runserver_plus … --cert-file … --key-file …` | HTTPS dev server (django-extensions) |
| `db` | `postgres:15` | 5432 | — | volume `youtube-organizer_postgres_data` |
| `frontend` | build `./frontend` (`node:20-alpine`) | 3000 | `next dev --experimental-https` | dev server |

- Both app services mount self-signed certs from `backend/certs/` and `frontend/certs/`
  (generated by `bin/generate-all-certs.sh`).
- `frontend` depends on `backend`; `backend` depends on `db`.
- Env comes from `backend/.env` and `frontend/.env` (`env_file`).
- `restart: unless-stopped` on all three.

## Build & Run

```sh
make up                 # docker-compose up --build
make backend-migrate    # apply migrations inside backend container
```

## Infrastructure Requirements (target production)

None of the following exists yet — these are the requirements to make this deployable:

- **App servers:** replace `runserver_plus` with a WSGI/ASGI server (gunicorn/uvicorn) behind
  a real TLS-terminating reverse proxy (nginx/Caddy/managed LB). Replace `next dev` with
  `next build` + `next start` (or static/edge hosting).
- **Real certificates** (not self-signed) for whatever domains replace `localhost:3000/8000`.
- **Managed Postgres** (or a hardened `db` service with backups/persistence).
- A **`docker-compose.prod.yml`** (does not exist yet).

(authoritative for **intent**). The actual workflow files under `.github/` are **unadapted

  `DEPLOY_APP_PATH`.

  applicable ones (money-as-string, 70% coverage, tests map to acceptance criteria).
